เมเชอร์Measureสูตรสรุปตัวเลข (รวม/เฉลี่ย/%) ที่คิดใหม่ทุกครั้งที่ผู้ใช้กดตัวกรอง

⭐ จัดตารางแบบดาว (Star Schema)

คำถามแรกที่ต้องตอบให้ได้: ตารางนี้บันทึก "เหตุการณ์" หรือเป็น "ทะเบียนรายชื่อ"? ตอบข้อนี้ถูก แล้วที่เหลือจะง่ายไปหมด

แยกให้ออกด้วย 3 คำถามนี้

คำถามถ้าตอบแบบนี้ = Factถ้าตอบแบบนี้ = Dimension
ตารางนี้โตขึ้นเรื่อย ๆ ไหมโตทุกวัน มีแถวใหม่ตลอดเกือบคงที่ นาน ๆ เพิ่มที
มีตัวเลขที่เอาไปบวกกันได้ไหมมี — กิโลกรัม, บาท, จำนวนชิ้นไม่มี หรือมีแต่บวกแล้วไม่มีความหมาย
จะเอาไปทำปุ่มตัวกรองไหมไม่ — ไม่มีใครกรองด้วย "ยอดขาย 1,234 บาท"ใช่ — กรองด้วยชนิดพืช จังหวัด เดือน

✅ กฎเดียวที่ต้องจำ: เส้นเชื่อมที่ถูกต้องเกือบทั้งหมดเป็นแบบ 1 ต่อกลุ่ม (One-to-Many) — ฝั่ง "1" คือ Dimension (แต่ละรหัสมีแถวเดียว) · ฝั่ง "กลุ่ม" คือ Fact (รหัสเดียวโผล่ได้หลายพันแถว) และ ตัวกรองไหลจาก Dimension ลงไป Fact ทางเดียว เหมือนน้ำไหลลงจากที่สูง
⚠️ ความผิดพลาดอันดับ 1 ของนิสิต: ยัดทุกอย่างไว้ตารางเดียวแบบ Excel ผลคือชื่อพืชถูกเขียนซ้ำหมื่นครั้ง ไฟล์บวม แก้ชื่อพืชทีต้องไล่แก้ทุกแถว และทำ Slicer ที่ใช้ร่วมกันหลายกราฟไม่ได้

🔍 ทำไมต้องมีตารางวันที่ (Date Table) แยกออกมา?

ฟังก์ชันเทียบเวลาทุกตัว (TOTALYTD, SAMEPERIODLASTYEAR) ต้องการปฏิทินที่ ครบทุกวันแบบไม่ขาด แม้วันนั้นจะไม่มีการเก็บเกี่ยวเลยก็ตาม

❌ ถ้าไม่มี DimDate จะเจอ 3 อาการนี้

  • กราฟขาดช่วง เพราะวันที่ไม่มีเก็บเกี่ยวหายไปจากแกน
  • เทียบปีต่อปีเพี้ยน เพราะสองปีมีจำนวนวันไม่เท่ากัน
  • มี 2 Fact (Harvest, Shipment) แต่กรองพร้อมกันด้วยตัวกรองเดียวไม่ได้

✅ สร้าง DimDate แล้วเชื่อมทั้งสอง Fact

DimDate = CALENDAR(DATE(2024,1,1), DATE(2026,12,31)) -- แล้วเพิ่มคอลัมน์ (Calculated Column) ปี = YEAR([Date]) เดือน = FORMAT([Date],"MMM") ไตรมาส = "Q" & QUARTER([Date]) ฤดูกาล = IF(MONTH([Date]) IN {11,12,1,2}, "ฤดูหนาว", IF(MONTH([Date]) IN {3,4,5}, "ฤดูร้อน", "ฤดูฝน"))
CALENDAR สร้างแถววันที่ต่อเนื่องให้อัตโนมัติ · คอลัมน์ที่เพิ่มทีหลังคือสิ่งที่เราเอาไปทำ Slicer และแกนของกราฟ
⚠️ กับดักที่เจอกันทุกคน: FORMAT([Date],"MMM") ให้ผลเป็นข้อความ พอเอาไปวางแกนกราฟจะเรียงตามตัวอักษร (ก.พ. ก.ค. ก.ย. …) ไม่ใช่ตามลำดับเดือน
วิธีแก้: เพิ่มคอลัมน์ เลขเดือน = MONTH([Date]) แล้วเลือกคอลัมน์ "เดือน" → Column tools → Sort by column → เลขเดือน
⚠️ ขั้นตอนที่ลืมกันบ่อยที่สุด: เลือกตาราง DimDate → Table tools → Mark as date table
ถ้าลืม Time Intelligence จะ ไม่ error แต่ให้คำตอบผิดเงียบ ๆ ซึ่งอันตรายกว่า error มาก

🧾 DAX คืออะไร

DAX ย่อมาจาก Data Analysis Expressions — คือ ภาษาสูตรของ Power BI ใช้เขียนบอกโปรแกรมว่า "ตัวเลขที่อยากเห็นบนแดชบอร์ด คำนวณมาจากอะไร"

ถ้า Excel ใช้สูตรอย่าง =SUM(B2:B50) เพื่อสร้างตัวเลขในเซลล์ — Power BI ก็ใช้ DAX เพื่อสร้างตัวเลขเช่นกัน ทุกตัวเลขบนแดชบอร์ดล้วนมาจากสูตร DAX ทั้งสิ้น ไม่มีตัวไหนที่พิมพ์ลงไปตรง ๆ

✅ DAX สร้างของให้เรา 2 อย่างเท่านั้น — Calculated Column (คอลัมน์ใหม่ในตาราง) และ Measure (สูตรสรุปตัวเลข) สองอย่างนี้ต่างกันอย่างไรและใช้เมื่อไร คือเนื้อหาของหน้าถัดไป

หน้าตาของสูตร DAX

ชื่อที่เราตั้ง = ฟังก์ชัน( ตาราง[คอลัมน์] ) ตัวอย่าง: ยอดขายรวม = SUM( FactHarvest[ยอดขาย] )
ชื่อที่เราตั้ง → จะไปโผล่ในรายการฟิลด์ให้ลากไปวางบนกราฟ · ฟังก์ชัน → คำสั่งสำเร็จรูป (SUM, AVERAGE, DIVIDE, CALCULATE …) · ตาราง[คอลัมน์] → บอกว่าจะเอาข้อมูลจากไหน
กลุ่มฟังก์ชันตัวอย่างใช้ทำอะไร
รวมค่าAggregationSUM, AVERAGE, MIN, MAX, COUNTROWSสรุปทั้งคอลัมน์ให้เหลือตัวเลขเดียว — ใช้บ่อยที่สุด
คิดทีละแถวIterator (ลงท้ายด้วย X)SUMX, AVERAGEX, MAXXเดินดูทีละแถว คูณ/หารก่อน แล้วค่อยสรุป
ตรรกะและความปลอดภัยLogicalIF, SWITCH, DIVIDEตั้งเงื่อนไข และหารอย่างปลอดภัยเมื่อตัวหารเป็นศูนย์
เปลี่ยนตัวกรองFilterCALCULATE, FILTER, ALLกำหนดเองว่าจะให้สูตรเห็นแถวไหน — มีหน้าเฉพาะให้ทั้งหน้า
เทียบเวลาTime IntelligenceTOTALYTD, SAMEPERIODLASTYEARเทียบปีนี้กับปีก่อน คิดยอดสะสม
ข้ามตารางRelationshipRELATED, RELATEDTABLEดึงค่าจากตารางที่เชื่อมความสัมพันธ์ไว้
💡 ไม่ต้องท่องทั้งหมด — DAX มีฟังก์ชันหลายร้อยตัว แต่งานจริง 90% ใช้แค่ราว 10 ตัวที่อยู่ในตารางนี้ และเราจะได้ลองเขียนทีละตัวในหน้า "ห้องทดลอง DAX"
⚠️ ข้อควรระวัง: ชื่อฟังก์ชันหลายตัวเหมือน Excel เป๊ะ (SUM, IF, AVERAGE) แต่พฤติกรรมไม่เหมือนกัน — ใน Excel เราบอกว่า "เอาเซลล์ไหน" ส่วนใน DAX เราบอกแค่ "เอาคอลัมน์ไหน" แล้วปล่อยให้ตัวกรองเป็นตัวกำหนดว่าจะนับแถวไหนบ้าง
คำถามยอดฮิตในการสอบ

🆚 Calculated Column กับ Measure ต่างกันอย่างไร

สองอย่างนี้เขียนด้วยภาษา DAX เหมือนกัน หน้าตาคล้ายกันมาก แต่ ทำงานคนละเวลา — และนั่นคือความต่างทั้งหมด

Calculated Column
  • คิด ทีละแถว ตอนโหลดข้อมูล
  • ผลลัพธ์ถูกเก็บจริงในไฟล์ → กินพื้นที่ ไฟล์ใหญ่ขึ้น
  • ค่าคงที่ ไม่เปลี่ยนตาม Slicer

กราฟแสดงค่าของสูตรที่เลือก แยกตามเดือน ภายใต้ตัวกรองปัจจุบัน — สังเกตว่าเปลี่ยนตัวกรองแล้วทั้งตัวเลขและกราฟขยับพร้อมกัน

⚠️ จุดพลาดที่ 1: เฉลี่ยแบบไม่ถ่วงน้ำหนัก (SUM vs SUMX)

-- ❌ ผิด ราคาเฉลี่ยผิด = AVERAGE( DimCrop[ราคาต่อกก.] )
ราคาเก็บอยู่ในตาราง DimCrop ซึ่งมีแค่ 3 แถว การเฉลี่ยแบบนี้จึงให้น้ำหนักพืชที่ขายได้ 10 กก. เท่ากับพืชที่ขายได้ 5,000 กก.
-- ✅ ถูก ราคาเฉลี่ยถูก = DIVIDE( SUMX( FactHarvest, FactHarvest[ปริมาณกก.] * RELATED(DimCrop[ราคาต่อกก.]) ), SUM( FactHarvest[ปริมาณกก.] ) )
สังเกตตัว X ท้ายชื่อ: ฟังก์ชันที่ลงท้ายด้วย X (SUMX, AVERAGEX, MAXX) แปลว่า "เดินดูทีละแถวก่อน แล้วค่อยสรุป" — ใช้เมื่อสูตรต้องคูณหรือหารกันในระดับแถว

⚠️ จุดพลาดที่ 2: หารด้วยเครื่องหมาย / ตรง ๆ

-- ❌ เสี่ยง error % ของเสีย = SUM( FactHarvest[ของเสีย] ) / SUM( FactHarvest[ปริมาณกก.] )
พอผู้ใช้กรองจนไม่เหลือข้อมูล ตัวหารกลายเป็น 0 → การ์ดจะขึ้นคำว่า Infinity หรือ NaN (กรณี 0 ÷ 0) ซึ่งดูไม่เป็นมืออาชีพเมื่ออยู่บนหน้าจอผู้บริหาร
-- ✅ ปลอดภัย % ของเสีย = DIVIDE( SUM( FactHarvest[ของเสีย] ), SUM( FactHarvest[ปริมาณกก.] ) )
DIVIDE เจอตัวหารเป็นศูนย์จะคืนค่าว่าง (BLANK) แทน — การ์ดแสดงเป็นช่องว่างเรียบร้อย และถ้าอยากให้ขึ้นเลข 0 ก็ใส่ตัวเลือกที่ 3 ได้: DIVIDE(a, b, 0)
⚠️ กฎเหล็ก: ใน Power BI ให้ใช้ DIVIDE(a, b) แทน a / b เสมอ ไม่มีข้อยกเว้น

ทำ / ไม่ทำ

✅ ทำ

  • วาง KPI สำคัญที่สุดมุมบนซ้าย (สายตาคนอ่านเริ่มที่นั่น)
  • ใส่ค่าเปรียบเทียบเสมอ — เป้าหมาย หรือ ปีก่อน
  • ใช้สีสื่อความหมายเท่านั้น: เขียว = ดี, แดง = ต้องแก้ และใช้ให้น้อยที่สุด
  • ตั้งชื่อกราฟเป็น "ข้อสรุป" ไม่ใช่ชื่อฟิลด์ — เช่น "ผลผลิตโรงเรือน C ต่ำกว่าเป้า 12%" ดีกว่า "ผลผลิตแยกตามโรงเรือน"
  • 1 หน้า = 1 คำถามธุรกิจ

❌ ไม่ทำ

  • ยัดกราฟ 12 อันในหน้าเดียว
  • ใช้กราฟวงกลมที่มีมากกว่า 5 ชิ้น (ตาคนเทียบมุมไม่เก่ง)
  • กราฟ 3 มิติ หรือใส่เงา — บิดเบือนการอ่านค่า
  • แกน Y ของกราฟแท่งไม่เริ่มที่ศูนย์ (ทำให้ความต่างดูเว่อร์เกินจริง)
  • ใช้สีรุ้งทั้งหน้าโดยไม่มีความหมาย

✅ เช็กลิสต์ก่อนส่งงาน

ไล่ทีละข้อให้ครบก่อนกดส่งงาน

  • ตารางถูกแยกเป็น Fact และ Dimension แล้ว ไม่ใช่ตารางเดียวยาว ๆ
  • มี DimDate และกด Mark as date table แล้ว
  • เส้นความสัมพันธ์เป็น One-to-Many และทิศทางเดียว
  • มี Measure อย่างน้อย 5 ตัว และตั้งชื่อเป็นภาษาคน (ไม่ใช่ Measure 1, Measure 2)
  • ใช้ DIVIDE ทุกที่ที่มีการหาร
  • มีสูตรเทียบเวลาอย่างน้อย 1 ตัว (YTD หรือ YoY)
  • มีการ์ดสรุปอย่างน้อย 2 ใบ พร้อมค่าเปรียบเทียบหรือเป้าหมายกำกับ
  • ทุกการ์ด KPI มีค่าเปรียบเทียบ ไม่ใช่ตัวเลขลอย ๆ
  • กดทุก Slicer แล้วไม่มีการ์ดไหนขึ้น error หรือค่าว่างแปลก ๆ
